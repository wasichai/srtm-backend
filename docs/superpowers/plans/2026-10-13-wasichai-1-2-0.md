# Subir a wasichai 1.2.0: plan y evaluación de riesgos

**Objetivo:** srtm-backend pasa de `wasichai-bom` 0.6.0 a **1.2.0**, la última versión publicada (2026-10-11). Cruza
1.0.0, 1.1.0 y 1.2.0 y adopta solo el comportamiento por defecto. Las mejoras nuevas quedan anotadas como seguimiento.

**Spec:** el pedido del usuario (2026-10-13): «adopta la última versión de wasichai».

## Qué trae wasichai

Revisado contra `CHANGELOG.md` y el diff `v0.6.0..v1.2.0` de wasichai/wasichai:

- **1.0.0** (2026-10-10). No hay commits que rompan: el salto a 1.0 es un `release-as`.
  - Zona horaria opcional en campos DATETIME (ADR-063), IANA o un desfase UTC fijo. `CustomField.timeZone` y la
    migración core **V18** (`ALTER TABLE custom_fields ADD COLUMN time_zone text`).
  - Máscara de lectura por campo (`RecordReadMask`) y política de lectura de los descriptores FILE.
- **1.1.0** (2026-10-11). Caché de las definiciones de objetos (ADR-066, `wasichai.metadata.cache.ttl`, 5 s) y acceso
  del usuario leído una vez por request (`RequestMemo`, `RoleQueries.objectAccess`).
- **1.2.0** (2026-10-11). La misma caché cubre workflows, automatizaciones, reglas, relaciones y campos FILE (ADR-067).
- **Build:** Kotlin 2.4.20, Spring Boot 4.1.1, ktlint 14.2.0/1.7.1 y jackson3 3.2.3, iguales a los de srtm.

## Compatibilidad del código de srtm

- Las APIs de core que srtm importa no cambian de firma. Los parámetros nuevos van al final y tienen valor por defecto:
  - `CustomField(..., timeZone = null)`: `BusquedaPrediosTest` y `RegistrosTest` lo construyen posicionalmente y siguen
    compilando;
  - `MetadataService(..., changes)` y `RecordService(..., masks)`: srtm no los construye a mano.
- `IdentidadEmision` solo usa `RoleQueries.roleNamesOf`, que sigue igual.
- srtm no escribe la metadata de core por SQL, así que la caché no queda desactualizada por algo que haga srtm.
- Los roles de srtm no tienen permisos por campo, así que la máscara de lectura no oculta nada.

## Riesgos

| Riesgo | Impacto | Mitigación |
| --- | --- | --- |
| V18 no tiene vuelta atrás | Bajo: una columna nullable, sin mover datos | `pg_dump` antes de arrancar 1.2.0 |
| Caché de metadata entre instancias | Un `apply.py` contra un nodo se ve en los otros hasta 5 s después | Esperar el ttl, o `wasichai.metadata.cache.ttl=0` |
| Máscara por campo / descriptores FILE | Ninguno hoy: srtm no usa permisos por campo | Revisarlo si se agregan |
