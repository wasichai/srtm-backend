# Subir a wasichai 0.3.2 y retirar IndicesArbitrios y CuotasInmutables: plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDA: usar superpowers:subagent-driven-development (recomendada) o
> superpowers:executing-plans para implementarlo tarea por tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** srtm-backend pasa a `wasichai-bom` 0.3.2. Se retiran los workarounds que 0.3.x vuelve innecesarios:
`IndicesArbitrios`, `CuotasInmutables` y el decorador `AlmacenGuardado` del `RecordStore`. Lo que no se migra queda
anotado con su motivo. Cierra wasichai/srtm-backend#76.

**Arquitectura:**
- Los índices `(anio, predio)` y `(anio, contribuyente)` y la regla de «solo agregar» pasan al modelo, en `model.json`:
  `indexes` y `appendOnly` (ADR-036 y ADR-040). Los aplica `apply.py`, y el test los aplica igual.
- `AlmacenGuardado` era un `RecordStore` que envolvía un `PhysicalTableRecordStore` reconstruido a mano. Pasa a ser
  `GuardiaDeEscritura`, un único `RecordWriteGuard` que despacha a las `ReglaDeEscritura` de siempre. Las reglas de
  sanciones y anuncios no cambian.
- `CuotasInmutables` se reduce a `ReglaDeArbitrios`, que solo valida las invariantes al dar de alta una cuota. Los 409
  los da core por `appendOnly`.
- `Registros.all` y `Registros.donde` leen con cursor (`count=false` y `after`): una sola pasada, sin `COUNT(*)`.

**Stack:** Kotlin 2.4 y Spring Boot 4.1 (WebFlux y corrutinas), wasichai 0.3.2, JUnit 5 con `WasichaiIntegrationTest`
(Testcontainers o PostGIS externo) y Python 3 en `model/` (`apply.py`, con `fake_core.py` en los tests).

**Spec:** wasichai/srtm-backend#76 y su comentario. Las decisiones del usuario (2026-10-06):
- versión 0.3.2;
- «guard adaptador» para `AlmacenGuardado`;
- git: rama, commits, push y PR contra `main`, sin mezclar nunca.

Referencias de wasichai, en el checkout `../wasichai` con el tag `v0.3.2`: `CHANGELOG.md`;
`wasichai-core/.../data/RecordWriteGuard.kt`; `RecordService.kt` (`asPlatform`, y el orden permisos → guards → store);

## Foco de revisión

1. **Un registro al que apunta una cuota no se borra.** Con `appendOnly`, borrar un `predio`, `contribuyente`,
   `servicio_arbitrio` o `parametro_tributario` al que apunta una cuota responde 409. Antes se podía. Se fija con un test
   en la tarea 3.
2. **Escritura de la plataforma o de una automatización** (`userId` nulo, sin la marca) sobre un objeto
   `soloDesdeElServicio` responde 403. Para un objeto de arbitrios pasa. Test unitario en la tarea 2.
3. **Relación inexistente por la API genérica.** Core revisa los destinos (D29) antes que los guards de la app. Un POST
   genérico con un id que no existe responde 400, no 403, y no escribe nada. El test de la API genérica tiene que usar
   ids reales para probar el 403. Tarea 2.
4. **Cierre del CUIS por el guard.** `before` es la fila guardada y `attributes` lo que manda quien llama. Un campo que
   falta en el pedido cuenta como null: core lo borra, igual que antes. El cierre válido pasa y cualquier otro cambio da
   409. Tareas 2 (unitario) y 2 (API).
5. **Listas de más de una página.** `Registros.all` con 201 filas o más las devuelve todas, sin repetir ni perder
   ninguna, en el orden pedido y también en descendente. Test en la tarea 1.
6. **`apply.py` dos veces seguidas:** la segunda no escribe nada. Y con un objeto ya creado sin `indexes` ni
   `appendOnly` (la base de dev), los agrega con un PUT. Test en la tarea 3.

  package srtm

  // rentas' GRANT INSERT, SELECT: what srtm only adds (an acta, an anuncio...) is never updated nor deleted, by anyone.
  // wasichai calls every RecordWriteGuard before the store, on every path (RecordService, links, workflow transitions,
  // automations, the platform: ADR-040), in the caller's coroutine, after the caller's permissions, appendOnly and the
  // relation targets (D29). this one asks each object's ReglaDeEscritura:
  // - an insert holds its invariants, whoever sends it (400); one of an object soloDesdeElServicio without the mark
  //   EscrituraDeSrtm is a 403 before anything is written (the platform and automations carry no mark either);
  // - an update is what the rule allows (by default nothing: 409), and with the mark when soloDesdeElServicio;
  // - a delete or a state transition is a 409, always.
  // a refusal for the missing mark leaves a WARN line that starts with ESCRITURA FUERA DE SRTM RECHAZADA. what it does
  // not see: a direct write to the database (the lotes' states, srtm.emision.TablasCore) and a module that writes
  // through the RecordStore without RecordWriteGuards
  @Component
  class GuardiaDeEscritura(
      reglas: List<ReglaDeEscritura>
  ) : RecordWriteGuard {
      private val log = LoggerFactory.getLogger(javaClass)

      private val porObjeto: Map<String, ReglaDeEscritura> =
          reglas.flatMap { regla -> regla.objetos.map { it to regla } }.groupBy({ it.first }, { it.second }).mapValues { (objeto, suyas) ->
              check(suyas.size == 1) { "«$objeto» tiene ${suyas.size} reglas de escritura: una como mucho" }
              suyas.single()
          }

      override suspend fun beforeWrite(change: RecordWrite) {
          val regla = porObjeto[change.objectName] ?: return
          val objeto = change.objectName
          when (change.kind) {
              RecordChangeKind.CREATED -> {
                  exigirLaMarca(regla, "CREATE", change)
                  regla.alInsertar(objeto, change.attributes.orEmpty())
              }
              // the rule compares the whole row: core's update replaces every field it is given, and one missing from
              // the request is cleared
              RecordChangeKind.UPDATED -> {
                  val guardado = change.before.orEmpty()
                  val nuevo = change.attributes.orEmpty()
                  val campos = guardado.keys + nuevo.keys
                  regla.alActualizar(objeto, campos.associateWith { guardado[it] }, campos.associateWith { nuevo[it] })
                  exigirLaMarca(regla, "UPDATE", change)
              }
              RecordChangeKind.DELETED -> regla.alBorrar(objeto)
              RecordChangeKind.TRANSITIONED -> regla.alCambiarDeEstado(objeto)
          }
      }

      private suspend fun exigirLaMarca(regla: ReglaDeEscritura, operacion: String, change: RecordWrite) {
          if (!regla.soloDesdeElServicio || currentCoroutineContext()[EscrituraDeSrtm.Clave] != null) return
          val objeto = change.objectName
          log.warn(
              "ESCRITURA FUERA DE SRTM RECHAZADA: {} {} {} por el usuario {} de la organización {}",
              operacion, objeto, change.recordId ?: "(alta)", change.userId ?: "(plataforma)", change.organizationId
          )
          throw ForbiddenException(
              "«$objeto» solo lo escribe srtm, por su api (/api/srtm/...), que corre sus reglas. La API genérica no las corre, " +
                  "y no lo escribe nadie por ella, tampoco un ADMIN"
          )
      }
  }

  ```python
  RULE_KEYS = ("indexes", "appendOnly")

  def rule_changes(obj, current):
      """The object-level rules model.json declares and Core lacks: indexes (ADR-036), appendOnly (ADR-040). They go
      after the relationships, since an index can name a relation field. Only what differs is sent."""
      changes = {}
      want_indexes = [[f.lower() for f in s] for s in obj.get("indexes", [])]
      if want_indexes != (current.get("indexes") or []):
          changes["indexes"] = want_indexes
      if bool(obj.get("appendOnly")) != bool(current.get("appendOnly")):
          changes["appendOnly"] = bool(obj.get("appendOnly"))
      return changes
  ```

### Tarea 5: anotar lo que no se migra

**Archivos:** los comentarios de `src/main/kotlin/srtm/emision/TablasCore.kt`, `EstadoTrabajos.kt`,
`RetencionEmision.kt`, `EmisionMasivaService.kt` (~134), `IdentidadEmision.kt` (~17) y `MaquinaLotes.kt` (~127), de

**Decisión** (criterio 4 del issue): no se pasa nada a `asPlatform`, y se anota por qué en cada archivo.
- **Las máquinas de lotes** (`MaquinaLotes`, `EstadoTrabajos`, `EstadoEmisiones`, `LotesEmision`):
  - toman con `FOR UPDATE SKIP LOCKED`;
  - las transiciones son compare-and-set, condicionadas al estado, con el «antes» leído bajo bloqueo en la misma
    sentencia;
  - `procesados` suma lo de los lotes.

  `RecordService` no puede expresar nada de eso. El `ClusterLock` serializaría lo que hoy reparte `SKIP LOCKED`.
- **`RetencionEmision`:** el `UPDATE … WHERE archivo IS NOT NULL` es idempotente entre instancias. Con `asPlatform`
  haría falta leer, reemplazar la fila entera y tomar un `ClusterLock`, y no se gana nada. Queda como mejora posible.
- **`IdentidadEmision`:** la emisión y la determinación corren a propósito como el usuario que las lanzó, para que core
  revise sus permisos. `asPlatform` saltaría los permisos. Se queda, pero el comentario deja de decir «0.2.0 has no
  system context»: ahora es una elección.
- **`Duplicados`:** desde 0.3.0 core ya responde 409 con `errors[].field` (D23), pero en inglés. srtm lo sigue
